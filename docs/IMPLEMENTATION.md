# Implementation and file guide

## October 7, 2026 redesign implementation

HomeScreen and ChatComposer implement prompt-first creation and media attachments. AIWorkspace composes chat history, durable progress, plan/file approvals, ProjectMedia, the existing generated library, ProjectPlayer and AssistantTimeline. App owns navigation and export/history/settings dialogs. FileAccessPanel handles permission and local browsing; FileChangeCard handles exact approvals. Conversation groups each request with its persisted work trace and verified change summary; timeline summaries compare the starting and ending saved versions, and file summaries use completed receipts. New steps are published before each relevant tool action and updated on success, failure, or permission waiting.

ManualEditor retains the existing operation model and gesture timeline but extracts ManualLibrary and ManualInspector. Library payloads distinguish media, elements and transitions. transitionOps supplies available source handles by trimming the boundary where necessary, then applies a real transition in the same undo transaction. clipStyleAt is shared by normal clip and transition rendering so framing, adjustments and motion effects agree.

Automatic project creation uses ProjectLibrary plus ProjectBootstrap. The bootstrap persists the prompt before preparation, copies media atomically with stable asset IDs, and starts AI after playback readiness. Optional heavy analysis remains asynchronous. ProjectDB owns first-draft readiness and updates modification timestamps for committed versions.

FileAccess/ FileOperations execute in Electron main, not generated code. file-client bridges project tools through ProjectService. Approval waits checkpoint the pending call; execution receipts survive resume. Copy and text replacement use sibling staging paths. Cross-volume moves copy to the destination and then use OS Trash for the source, reporting partial outcomes if the second operation fails.

The cloud guest migration and access helper remove invitation requirements only for validated anonymous identities. The desktop Account class deduplicates guest enrollment, encrypts the session, refreshes it, and recreates a session only when its refresh credential is no longer valid.

This guide describes the current source and the required continuation points. It does not mark the full accepted product plan complete.

## Desktop packaging and lifecycle

- `apps/desktop/forge.config.ts` builds main, preload, service and renderer targets, stages resources and declares Windows Squirrel / Mac ZIP and DMG makers. Signing is conditional on supplied publisher credentials.
- `apps/desktop/copy-runtime.ts` resolves the actual installed production dependency closure, including required peers and platform-specific optional packages. Keep native dependency versions matched to the lockfile and Electron ABI.
- `apps/desktop/vite.{main,preload,service,renderer}.config.ts` defines process-specific compilation. Renderer deduplication is required for React, React DOM and Remotion; two React instances break the preview hooks.
- `apps/desktop/src/main/index.ts` owns the trusted window and bridge routing. Add new capabilities as validated commands or explicit methods, never raw IPC, arbitrary shell access or generic filesystem APIs.
- `src/main/service.ts` supervises the project utility process and correlates request/response IDs. Shutdown requests graceful cancellation before its bounded termination deadline.
- `src/main/{resources,media,rendering}.ts` resolve staged binaries, serve scoped assets with byte ranges, and export through a tokenized server. Exports use a captured asset map, a temporary MP4 and ffprobe validation before finalization.
- `src/main/{account,auth,models}.ts` implement encrypted refresh credentials, system-browser PKCE and resumable checksum-verified model downloads. Never move provider credentials into these files.
- `src/preload/index.ts` exposes `DreamDesktop`; `packages/contracts/src/index.ts` is the command/event boundary. Add matching request and result validation when expanding the bridge.
- `scripts/{build-remotion,stage-runtime,prepare-package}.ts` produce offline render resources. `scripts/stage-whisper.ps1` verifies and stages the pinned Windows Whisper binary. `patches/electron-winstaller@5.4.4.patch` corrects the upstream architecture-selection setup bug.

## Project service and persistence

- `apps/project-service/src/main.ts` dispatches serialized commands and coordinates background ingest and AI. Project switching waits for current workers to stop before closing the database.
- `src/locks.ts` acquires writer ownership without deleting a lock owned by another live process.
- `src/media.ts` registers fingerprints, probes source media, generates proxies, playback masters, thumbnails and waveform peaks, calls Whisper and invokes available analysis stages. Add stages through the shared job lifecycle; do not mark unavailable model work complete.
- `src/artifacts.ts` atomically publishes derived files after producer/validator success.
- `src/analysis-client.ts` launches a bounded local child with an explicit environment, validates structured responses, handles cancellation and limits output size. The child cannot write project history.
- `src/collect.ts` creates a coherent portable copy from SQLite backup state. It rewrites only the copied registry and publishes a complete folder by rename.
- `packages/project-db/src/index.ts` owns assets, footage records, FTS, versions, requests, actions, messages, jobs and events. New schema revisions belong in `src/migrate.ts`; preserve transactional version advancement and newer-version rejection.
- `packages/project-db/src/paths.ts` is the common portable-reference encoder/resolver. All additional artifact paths need the same relative-path rules.

## AI and local analysis

Tool mutations use stable turn/call IDs and expected versions. The 40-call budget is shared across the initial edit and repair passes. Persisted routes retain the correct edit, question or build phase on resume. - `packages/footage/src/context.ts` builds paginated asset catalogs and source-range word/shot reads, omitting local paths. `packages/orchestrator/src/footage-tools.ts` validates catalog/search/read inputs and adds source timing plus nearby transcript to local FTS results. Routine prompts carry samples instead of the full transcript.
- `packages/orchestrator/src/read-loop.ts` persists provider responses and completed read results for planning and questions. Read-only requests are bounded independently of the 40-call editor budget; resumption reuses already obtained context.
- `packages/orchestrator/src/{review-packet,review-loop}.ts` select at most 16 opening/cut/effect frames, attach all cut and story-beat timing plus the shared sample audio manifest, and pass only referenced assets/source words to the local render request, validate reviewer findings, and checkpoint up to two review rounds. A repair pass has its own resumable tool checkpoint and remains part of the same undo action. Reports describe sampled visual evidence and never claim an audio listening test.
- `packages/contracts/src/review.ts` validates internal render requests, image responses and structured review findings.
- `apps/desktop/src/main/{review-rendering,render-server,media-response}.ts` render JPEG evidence with the packaged composition/browser, cache by bundle content and immutable request, and serve only snapshot-owned assets on a tokenized loopback endpoint. `service.ts` and the project-service entrypoint provide a narrow cancellable reverse request; the renderer UI receives no new filesystem or render privilege.
- `apps/ingest-worker/src/dream_ingest/{main,pipeline}.py` implement the offline JSON-line stage protocol, cache identity and artifact hashes. `audio.py` processes PCM in blocks. `vision.py` provides MediaPipe and local SigLIP adapters.
- `apps/ingest-worker/{pyproject.toml,uv.lock}` pin runtime dependencies. `build/{entry.py,runtime.spec}` freeze the worker. Validate the frozen result and include all dynamic libraries, approved weights and notices; development imports are insufficient release evidence.

## Targeted context, model choice and shared creative direction

This change replaces the default full-timeline/full-operation-schema prompt with local retrieval and progressive tool loading. It follows the general approach described in [Cursor's context guide](https://docs.cursor.com/en/guides/working-with-context); Dream uses local SQLite FTS5, selection and position signals, plus model-proposed query expansion. This is not a claim of equivalent embedding search. Stable tool ordering and shared instructions preserve reusable cache prefixes within each capability profile, following [Anthropic's caching contract](https://platform.claude.com/docs/en/build-with-claude/prompt-caching). Loading a new profile changes that prefix and may incur a new cache write.

- `packages/project-db/src/migrate.ts`: migration 4 adds disposable `context_chunks` and FTS5 `context_fts`. Original project records remain authoritative. Chunk IDs identify record kind, owner and sequence; content hashes avoid rewriting unchanged rows. The normal SQLite backup/collection includes the derived index.
- `packages/orchestrator/src/context.ts`: index timeline items, beats, captions, safe asset metadata, saved definitions/code, messages, preferences and pending plans. Refresh against project head, analysis revision, preferences, plans, library and message changes. Rank matching chunks using FTS5; prioritize selected occurrences and relevant opening/ending clips. Bound automatic excerpts to 14,000 characters plus a small overview, direction and source-hit allowance. Exact chunk reads return continuation IDs. `get_project` pages timeline/assets/plan; it no longer dumps the document or source paths. Local footage search stays in its existing index.
- `packages/orchestrator/src/routing.ts`: classify only clearly direct timeline requests locally, without executing anything. Ambiguous or creative briefs use a compact Haiku request containing counts/settings rather than footage or the timeline. Its validated decision includes route, Sonnet/Opus intelligence, initial capability groups and up to three query expansions. Sonnet is the normal executor and planner. Complex concept choices or explicit requests can obtain initial Opus guidance. Generated-only scenes route to creation, without requiring imports.
- `packages/orchestrator/src/tool-context.ts`: expose a small permanent editing/retrieval/report/consultation surface; select initial footage, visual, audio and history tools from the request/router. `load_tools` expands capabilities in the same loop, with groups saved in its checkpoint. `get_operation_schema` retrieves exact operation types on demand; a small quick reference covers common edits. Local `OpSchema` validation remains authoritative for every mutation.
- `packages/orchestrator/src/index.ts`: use bounded context at routing, planning, editing, recovery and consultation boundaries. Persist routing decisions. Use compact operation arguments instead of embedding the complete union schema. A final simple `apply_ops` can include `finish.summary`; completion is recorded only after a successful validated batch, removing a summary-only model call. Pending reviews cannot use this shortcut. Return compact mutation receipts rather than copying the entire resulting timeline into model context. Page sound catalogs instead of returning all presets and saved documents.
- `packages/orchestrator/src/design.ts`: stable shared craft standards cover concept/theme, hierarchy, typography, composition, aspect ratio, coherent motion, pacing, audio and evidence-based checks. Explicitly support original coded scenes when footage is absent, mood/pacing requests across modalities, saved reusable definitions, and chat-driven creation. No prompt can guarantee creative quality; rendered evidence and evaluation remain necessary.
- `packages/orchestrator/src/director-consult.ts`: Opus returns implementable instructions, optional concrete design-system choices and acceptance checks. Its read-only loop can retrieve exact missing context. `read-loop.ts` supplies bounded project reads and optional consultation for Sonnet planning/question flows; Opus does not recursively consult itself. A planner must receive guidance before submitting its final plan.
- `packages/orchestrator/src/review-loop.ts`: use the same craft standards with Sonnet for normal rendered reviews. Editor consultation remains available for difficult repairs. Sparse images are never described as motion or audio playback proof.
- `packages/orchestrator/src/inference.ts`: record context-size/tool-count metadata without recording prompt contents in cloud logs. Existing durable response caching, prompt caching, retries and adaptive output capacity remain in place.
- `apps/desktop/src/renderer/components/media/MusicLibrary.tsx` and `App.tsx`: replace manual score construction/regeneration controls with browsing, audition and requests placed in the common chat composer. Saved code-based visuals are discoverable alongside audio. Selecting inspiration or requesting a variation does not itself mutate the timeline; the AI performs creation and placement after the user sends the instruction.
